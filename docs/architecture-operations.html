1System overview

BCJ Learn is a custom, BCJ-owned web application for delivering the five-module Account Manager training programme: hosting content, running on-site quizzes, enforcing the 85% pass rule and retakes, and giving leadership live reporting. It is a single web app - no software for users to install - that runs on professional cloud services, all set up under BCJ's own accounts.

This document is for whoever maintains the platform on BCJ's side (IT, or a future support partner). It explains what the platform is built on, where each piece lives, and how to perform the common operational tasks. It does not require day-to-day code changes - the platform is built to run Modules 2-5 with no engineering work.

4Hosting & deployments

The app is hosted on Vercel and connected to the GitHub repository. Deployment is automatic:

  • A change is pushed to the GitHub repo's main branch.
  • Vercel automatically builds it and, if the build passes, publishes it to the live URL within a couple of minutes.
  • Every deployment is kept in history, so a previous version can be restored instantly.

To roll back: Vercel dashboard → Deployments → pick a known-good deployment → Promote to Production. No code or rebuild needed.

No manual server administration is required. Vercel handles HTTPS certificates, scaling and uptime automatically.

5Database & data

All data lives in a single Supabase PostgreSQL database - user accounts, modules, content, questions, quiz attempts, results, resources and notifications. Key points for whoever maintains it:

  • Schema changes are managed as numbered SQL migration files in the codebase under supabase/migrations/ (52 to date). They are applied in order via the Supabase SQL editor.
  • Row-Level Security (RLS) is enabled on the tables: the database itself enforces who can read or write what (e.g. an employee can only see their own attempts). This is a core security layer, not just app logic.
  • Business rules such as starting a quiz and grading run as secure database functions (RPCs), so the rules hold even if called directly.
  • Quiz integrity: the same question pool is served in a randomised order; the 85% threshold, the 3-attempt limit and the easier retake pool are all enforced server-side.
Care with the database: editing rows directly in Supabase bypasses the app's safeguards. Prefer the in-app Admin tools; use direct SQL only for maintenance, and take a backup first.

6Environment variables

The app is configured through environment variables held in Vercel → Project → Settings → Environment Variables (never in the code). The actual values are secret and are not printed here.

After changing any variable in Vercel, trigger a redeploy so the new value takes effect.

7Authentication & security

  • Sign-in: email + password, handled by Supabase Auth. Optional two-step verification sends a 6-digit code by email.
  • Password reset: self-service from the login screen via an emailed link.
  • Roles: Admin, Department Lead, Employee - enforced both in the app and at the database (RLS).
  • Encryption: all traffic is HTTPS; data is encrypted at rest by Supabase.
  • The service-role key is used only by trusted server code, never sent to the browser. Treat it, and all secret keys, like passwords.

8AI question generation

Quiz questions are drafted by OpenAI: GPT-4o reads the uploaded module content and writes the question bank; Whisper transcribes uploaded videos so their content can be used too. Nothing is published without a human approving it in the app.

  • The feature runs on the key in OPENAI_API_KEY. To run it on BCJ's own account, create a key at platform.openai.com, add it in Vercel, and redeploy.
  • Cost is usage-based and billed directly by OpenAI to the account that owns the key - typically modest at this scale.
An Anthropic (Claude) integration also exists in the code but is not currently used; AI runs on OpenAI.

9Email delivery

All automated email (invitations, sign-in codes, pass/fail results, reminders, at-risk alerts) is sent through Resend. The text of every email is editable by an Admin inside the app under Notifications.

  • Emails are sent from the address in RESEND_FROM_EMAIL.
  • For best deliverability the sending domain should be verified in Resend (DNS records added to BCJ's domain). Until then, sending may be limited.

13Monitoring & troubleshooting

  • App errors / logs: Vercel dashboard → the latest Deployment → Logs (runtime & function logs).
  • Database & auth logs: Supabase dashboard → Logs.
  • Email delivery: Resend dashboard → Emails (see what sent, bounced or failed).
  • In-app activity: the Admin Audit log records sign-ins, passes, publishes, reminders and more.

Common first checks: a failed AI generation usually means the OpenAI key is missing, unfunded or invalid; emails not arriving usually means the sending domain isn't verified or demo mode is on.

14Backups & disaster recovery

  • Database: Supabase takes automated backups (retention depends on the Supabase plan). Restores are done from the Supabase dashboard.
  • Code: the full history is in GitHub; any prior version can be restored or redeployed.
  • Deployments: Vercel keeps every previous build for instant rollback.
Recommended: confirm the Supabase plan's backup retention meets BCJ's needs, and keep at least one Admin and the IT account credentials stored in a company password manager.
